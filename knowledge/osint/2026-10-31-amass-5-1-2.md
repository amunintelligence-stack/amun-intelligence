# OWASP Amass v5.1.2 (25 Oct 2026)

**Date noted:** 2026-10-31
**Category:** osint / attack-surface mapping

## What changed
- **Amass v5.1.2** shipped **25 Oct 2026** (Apache 2.0), per a repository read dated 25 Oct 2026. It follows v5.1.1 (covered 2026-10-09), whose notes mention a **new asset database with schema changes**.
- Amass remains the passive + active attack-surface mapper: `amass enum` (collection session), `amass subs`, `amass track` (newly discovered assets), `amass viz` (graph output), `amass assoc` (asset relationships), `amass engine`. The older `amass intel` subcommand was dropped in v5.
- Practical setup note from the same survey: the Docker Compose example provisions a **PostgreSQL database**, so Amass v5 is heavier to stand up than a single binary — expect more setup than subfinder.
- Same survey's October-2026 maintenance snapshot for the subdomain layer: subfinder v2.17.0 (8 Oct), katana v1.8.0 (5 Oct), httpx v1.12.0 (8 Sep), nuclei v3.11.1 (8 Aug), ffuf v2.3.0 (9 Sep), dnsx v1.3.1 (31 Aug), BBOT v3.0.2 (24 Aug). Sublist3r and assetfinder remain unmaintained (no commits since 2020) — already recorded 2026-10-30.

## Why it matters for ACI
- Amass is the natural "deep" complement to subfinder in a mission pipeline: subfinder for fast passive breadth, Amass for the asset graph (domains → IPs → netblocks → ASNs → relationships) that feeds ACI's graph layer. The v5 asset database + `assoc`/`viz` outputs map directly onto entity/relationship ingestion.
- The Postgres-backed asset DB is a fit consideration, not a blocker: ACI already runs Postgres, so an Amass asset store could live beside it — but schema changes in v5.1.1 mean any importer must pin to the v5 schema, not v4.
- No urgency: this is a patch-level release in an already-tracked tool, not a new capability.
