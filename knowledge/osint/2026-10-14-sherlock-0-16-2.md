# Sherlock 0.16.2 patch release (8 Sep 2026)

**Date researched:** 2026-10-14
**Status:** Patch follow-up to v0.16.0 (covered 2026-10-11).

## What changed
- Sherlock published **v0.16.2 on 8 Sep 2026**, per the Bellingcat Online Investigation Toolkit entry (updated 28 Sep 2026). This is a patch release on top of v0.16.0 (Sep 2025), which introduced automatic filtering of false-positive-prone sites, `--no-txt`, `--json` PR-number manifests, PEP 561 compliance, and dropped Python 3.8/3.9.
- Packaging caught up in the same window: FreeBSD ports updated `py-sherlock-project` to 0.16.2 (11 Sep 2026, changelog ref `v0.16.0...v0.16.2`), and Kali's tracker lists `0.16.0-1` (imported 14 May 2026). The exact 0.16.1→0.16.2 patch notes were not pulled in this pass — the release is recorded here as a version bump, not a feature change.
- The tool itself is unchanged in role: username existence checks across 400+ sites, no API keys, `--site` scoping, `--csv`/`--xlsx` export, `--proxy`/`--tor`/`--unique-tor` options, `--local` / `--json` site-definition control.

## Why it matters for ACI
- Sherlock is ACI's canonical keyless username-enumeration tool for person-of-interest work. Patch releases in this project are usually site-definition fixes (detection logic for sites that changed their pages) — i.e. accuracy fixes that directly affect false-positive/false-negative rates on missions. Running a stale 0.16.0 means silently wrong answers on sites whose detection broke.
- Bellingcat's toolkit (a trusted OSINT reference) now pins 0.16.2 as current, so ACI's registry pin should match to stay aligned with the reference the team cites.
