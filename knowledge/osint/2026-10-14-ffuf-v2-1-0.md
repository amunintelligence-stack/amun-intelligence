# ffuf v2.1.0 — client-cert auth, in-flight encoders, wider default matching

**Date researched:** 2026-10-14
**Status:** Release-prep commit landed ~mid-Sep 2026 (crawled 13 Sep 2026). FreeBSD ports were already tracking 2.2.1 by 8 Oct 2026, so check the releases page for a newer tag before pinning.

## What changed
- ffuf v2.1.0 release preparation commit (`7a2756a`, "Prepare for v2.1.0 release (#724)") bumps `VERSION` from 2.0.0 to 2.1.0. Changelog contents, verified from the commit diff:
  - **New:** `-cc` / `-ck` flags for client-side certificate authentication; `-raw` flag to omit URL-encoding for URIs; `-enc` flag (via the `ffuf/pencode` library) for in-flight encodings of input data (e.g. `FUZZ:urlencode b64encode`); autocalibration-strategy refactored for extensible strategy configuration (`-acs` now accepts custom strategies, repeatable).
  - **Changed/fixed:** multiline output fix; explicit TLS 1.0 allowed; markdown and CSV output format fixes; divide-by-zero fix when rate limit set to 0 manually; **automatic brotli and deflate decompression**; timeout reported when a time-based matcher/filter is active; **all 2XX status codes now matched** — `-mc` default changed from `200,204,301,302,307,401,403,405,500` to `200-299,301,302,307,401,403,405,500`; config files may declare "unused" wordlists.
- Packaging signal: FreshPorts shows the FreeBSD `security/ffuf` port at 2.2.1 (port revision _2), last updated 8 Oct 2026 — i.e. upstream has moved past 2.1.0 already. The 2.2.1 changelog was not reviewed in this pass.

## Why it matters for ACI
- ffuf is ACI's content-discovery / fuzzing tool. Three items are directly useful for intel missions: `-cc`/`-ck` unlocks fuzzing mTLS-protected corporate portals (common in the corporate-intel target set); `-enc` removes the need for pre-encoded wordlists when probing WAF-filtered endpoints; automatic brotli/deflate decompression fixes a class of silent missed matches on modern servers.
- **Behavior-change warning:** the `-mc` default widening to all 2XX changes what counts as a "hit" versus previous runs. Any ACI baseline/comparison that assumes the old default (200,204 only in the 2XX range) will show new positives after upgrading — expected, not a regression, but diffs must be read with that in mind.
