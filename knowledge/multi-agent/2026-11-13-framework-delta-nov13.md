# دلتا الأطر متعددة الوكلاء — هجوم ToFu / «Repeat-After-Me»؛ MAF 1.26.0 اليوم؛ LangChain 1.5.0؛ A2A مستقر (13 نوفمبر 2026)

## 1. ⚠️ هجوم ToFu / «Repeat-After-Me» — ستة أطر تُجاوَز + 253 خطأ MCP موثَّقًا (ليس في السجل)

- **ما الذي تغيّر:** مسودة «ToFu: Exploiting and Fuzzing the LLM–Orchestrator–Tool Trust Boundary» (Penn State وUniversité Montpellier وDartmouth)، arXiv 2610.13651، نُشرت **9 أكتوبر 2026**؛ تغطية صحفية CSO Online **12 أكتوبر 2026**. نتيجتان: (أ) «Repeat-After-Me» — مهاجم يجعل النموذج يكرر نصًا كتبه المهاجم حرفيًا، وطبقة التنسيق تفسّر النص المكرر كاستدعاء أداة منظَّم وتنفّذه، حتى عندما يرفض نص النموذج نفسه. أُعيد إنتاجه على **LangGraph وMicrosoft Agent Framework وAutoGen وGoogle ADK 2.0 وAWS Strands وCrewAI** (النص الكامل منشور فقط لـ LangGraph 1.2.0 + Llama 3.1 8B عبر Ollama؛ الخمسة الأخرى أُعيد إنتاجها دون نصوص). (ب) مموِّه ToFu فحص 273 خادم MCP مفتوح المصدر (3,405 أدوات) ووثّق **253 خطأً في 343 أداة عبر 118 خادمًا** — 64 اجتياز مسار، 7 SSRF، 5 تسريب بيانات، 3 حقن أوامر نظام، إضافة إلى فئات حقن سجلات/مخرجات. الورقة لم تُراجَع بعد من الأقران؛ البائعون لم يردوا على الصحافة.
- **لماذا يهم ACI:** ذو صلة مباشرة. وكلاء OSINT في ACI يستوعبون نصًا يتحكم فيه المهاجم (صفحات ويب مكشوطة، منشورات اجتماعية) في سياق النموذج — وهي بالضبط قناة تسليم هذا الهجوم. السبب الجذري معماري (مكالمات الأدوات مخرجات منظمة موثوقة)، لا خطأ واحد قابل للترقيع، فلا ترقية إطار تصلحه. نتيجة تمويه MCP مهمة أيضًا: أي خادم MCP يوصله ACI يجب افتراض أن فيه عيوب تحقق وسيطات حتى يُفحص.
- **المصادر:** https://arxiv.org/abs/2610.13651 (9 أكتوبر 2026)؛ https://www.csoonline.com/article/4233811/researchers-bypass-6-ai-agent-frameworks-with-a-simple-repeat-after-me-prompt.html (12 أكتوبر 2026)
- **الإجراء: adopt (تخفيفات، لا رفع إصدار)** — عامل كل وسيطات مكالمات الأدوات كغير موثوقة: تحقق/عقّم الوسيطات من جانب الخادم في معالجات أدوات ACI (حصر المسارات، قوائم URL مسموحة، لا أسرار في نطاق الأداة)؛ لا تعطِ الوكلاء بيانات اعتماد قابلة للقراءة أبدًا؛ أضف تدقيق تحقق وسيطات على طراز ToFu لخوادم MCP الخاصة بـ ACI إلى قائمة الانتظار. يُعلَّم كعنصر الأمان الليلي.

## 2. Microsoft Agent Framework python-1.26.0 — وُسم اليوم (13 نوفمبر 2026، 08:28 UTC)

- **ما الذي تغيّر:** وسم GitHub `python-1.26.0` نُشر 13 نوفمبر 08:28 UTC (رفع PyPI كان 12 نوفمبر 18:25، سُجّل أمس؛ سجل التغييرات قُرئ الآن). أُضيف: `loop_return_final_only` في `create_harness_agent()`؛ `SecureAgentConfig.message_labeler` تجريبي — رد نداء لتصنيف مملوك للتطبيق لرسائل موفري السياق؛ دعم مخرجات منظمة في تكامل GitHub Copilot. **كاسر:** Copilot CLI ≥1.0.85 مطلوب عند البدء؛ صندوق Hyperlight الرملي يقاطع الآن الضيوف الملغاة ويفرض **ميزانية تنفيذ 30 ثانية افتراضيًا** (يحتاج Hyperlight SDK ≥0.9.0). **مهمل:** واجهتا `MemoryContextProvider`/`MemoryStore` التجريبيتان القديمتان، الإزالة بعد **31 ديسمبر 2026** — انتقل إلى `FileMemoryProvider` + `AgentFileStore` (ليس بديلًا مباشرًا: تخطيط مختلف، لا استخراج ذاكرة تلقائي، لا سجل نصوص، بنطاق جلسة افتراضيًا).
- **لماذا يهم ACI:** MAF هو المسار الحي من Microsoft بعد أرشفة AutoGen ومرشح إطار. إهمال واجهة الذاكرة له تاريخ صلب؛ خطاف `message_labeler` نمط دفاع ذو صلة مباشرة بالعنصر #1 (صنّف رسائل موفر السياق غير الموثوقة قبل وصولها إلى الوكيل).
- **المصادر:** https://github.com/microsoft/agent-framework/releases/tag/python-1.26.0 (13 نوفمبر 2026)
- **الإجراء: watch** — سجّل إهمال الذاكرة في 31 ديسمبر 2026 ونمط `message_labeler`؛ لا ترقية (ACI لا يشغّل MAF).

## 3. LangChain 1.5.0 + langchain-core 1.8.0 — 11 نوفمبر 2026

- **المصادر:** https://github.com/langchain-ai/langchain/releases/tag/langchain%3D%3D1.5.0 (11 نوفمبر 2026)؛ PyPI langchain-core 1.8.0 (11 نوفمبر 2026)

## 4. Google ADK 2.14.0 (7 نوفمبر) + 2.14.1 (12 نوفمبر) — A2A يتخرج إلى مستقر؛ AWS + Foundry تعتمدان A2A

- **ما الذي تغيّر:** ADK Python 2.14.0 (وسم GitHub ‏7 نوفمبر 00:58 UTC): **بروتوكول A2A وبيئات التنفيذ والتقييم تتخرج من التجريبي إلى المستقر**؛ **TeamsRunner** جديد لـ Microsoft Teams؛ CLI ‏`adk generate_agent_card`. Google تدّعي أن سير عمل 30 عقدة/200 دورة أسرع 23% مع ذروة ذاكرة أقل 9% — **غير مؤكد، بلا عتاد/خط أساس منشور**. 2.14.1 (12 نوفمبر 21:30 UTC) إصلاح خطأ من سطر واحد (تعطيل تتبع FastAPI الأصلي على Agent Engine). بشكل منفصل: **AWS أعلنت دعم A2A في 12 نوفمبر 2026** (اكتشاف بطاقة وكيل، OAuth 2.0/OIDC، تناظر عبر مؤسسات بين وكلاء LangChain/Strands)؛ **A2A v1.0 صار GA على Microsoft Foundry** (JSON-RPC فقط؛ المعاينة v0.3 كانت بنقل مزدوج)، مع عينات A2A من الدرجة الأولى لوكلاء MAF وLangGraph المستضافين.
- **لماذا يهم ACI:** A2A صار مستقرًا الآن في ثلاثة أماكن دفعة واحدة (ADK وFoundry وAWS) — قصة التشغيل البيني لتسليم المهام بين وكلاء ACI ووكلاء خارجيين/شركاء تستقر على A2A + بطاقات وكيل موقعة. ACI لا يشغّل ADK، فلا تغيير كود.
- **المصادر:** https://github.com/google/adk-python/releases/tag/v2.14.1 (12 نوفمبر 2026)؛ https://www.nglobenews.com/en/article/us-google-adk-2140-a2a-stable-teams-2026-11-08/ (8 نوفمبر 2026)؛ مدونة AWS ML عبر البحث، 12 نوفمبر 2026؛ https://medium.com/@manoranjan.rajguru/a2a-in-microsoft-foundry-making-your-hosted-agent-callable-by-agents-you-dont-own-29b804321fd6 (~10 نوفمبر 2026)
- **الإجراء: watch** — سجّل A2A v1.0 كافتراضي التشغيل البيني لأي تصميم تسليم عبر وكلاء مستقبلي؛ عامل ادعاء Google بالأداء 23% كتسويق حتى يُقاس.

## 5. deepagents 0.7.37 (12 نوفمبر) + 0.7.38 (13 نوفمبر، اليوم 14:32 UTC)

- **ما الذي تغيّر:** 0.7.38 إصلاح صندوق رملي ذو صلة بالأمان: نتائج `ls`/`grep`/`glob` تُستبعد الآن عندما يحل رابط رمزي خارج نطاق البحث المعتمد (PR #7706). 0.7.37 يخزّن عمليات بحث التخزين المؤقت للمطالبات الاختيارية. الوكلاء العميقون المُدارون من LangChain v0.10 يشحنون أيضًا أداة `browser_handoff` (إنسان يتولى المتصفح عند جدران تسجيل الدخول/2FA فلا تدخل بيانات الاعتماد آثار النموذج أبدًا) — ذُكر في كتابة 1 نوفمبر 2026.
