# وكيل واحد أم متعدد الوكلاء؟ إطار قرار للفرق المؤسسية (أكتوبر 2026)

**التاريخ:** 2026-10-15
**الفئة:** multi-agent

## ما الذي تغيّر
- نُشر في أكتوبر 2026 إطار قرار يقارن الوكيل الواحد مقابل الأنظمة متعددة الوكلاء، ويقارن LangGraph وCrewAI وAutoGen وMicrosoft Agent Framework.
- النقاط الجوهرية:
  - ابدأ بوكيل واحد. ابقَ معه عندما يكون العمل خطيًا، أو عندما تتسع نافذة سياق واحدة للمشكلة، أو عندما يحتاج المخرج إلى مالك واحد مسؤول، أو عندما يكون الفريق جديدًا على الوكلاء.
  - تكلفة التنسيق وأخطاء الحالة وعبء التقييم تأتي معًا ومتأخرة — العروض التوضيحية تجعل تعدد الوكلاء يبدو طبيعيًا، والإنتاج أقل مجاملة.
  - تأكيد حالة AutoGen: مستودع Microsoft يصفه بأنه في **وضع الصيانة** — لا ميزات جديدة، يُدار مجتمعيًا — ويوصي بـ **Microsoft Agent Framework** (1.0، GA أبريل 2026) للمشاريع الجديدة.
- في مقارنة موازية نُشرت في نفس الفترة: LangGraph هو الخيار الافتراضي للإنتاج (رسم بياني صريح + نقاط تحقق)، وCrewAI الأسرع للنموذج الأولي، وAutoGen يُنصح بالترحيل عنه.

## لماذا يهم ACI
- ACI نفسه مبني على 5 أنماط (تسلسل / توجيه / توازي / منسّق / مقيّم-محسّن). الإطار الجديد يدعم قاعدة تصميم مهمة: كل وكيل إضافي يجب أن يكسب مكانه بقياس، وليس بمجرد تقسيم الأدوار.
- عمليًا لمهام ACI: قبل إضافة وكيل جديد، نُثبت أن الوكيل الواحد بأدوات أفضل يفشل في مقياس محدد. هذا يقلل التكلفة والأعطال في مهام الاستخبارات الطويلة.

- نعتمد قاعدة «وكيل واحد أولًا + خط أساس مقاس» في تصميم مهام ACI: أي وكيل جديد يحتاج مبررًا بمقياس (دقة / زمن / تكلفة) قبل إضافته إلى المنسّق.
- نحدّث مراجع AutoGen في وثائق التصميم إلى Microsoft Agent Framework كمرشح أول للترحيل (تكرار لتوصية سابقة، وتأكيد جديد).
