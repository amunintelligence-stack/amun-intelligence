# Google ADK Python v2.9.0 (2026-09-10) — تجاوز تلقائي للموديلات؛ مخطط لمنطق تجاوز "الخزان"

- التاريخ: 2026-10-08 | الفئة: multi-agent | الإجراء: **مراقبة (watch)**

## ما الذي تغيّر
شحن ADK Python v2.9.0 تجاوزًا تلقائيًا للموديلات (الوكلاء يتحولون بشفافية لموديلات احتياطية عند تعطل الأساسي)، وLiveKit runner لوكلاء الصوت/الهاتف، وتأليف/تحميل YAML إعلانيًا لسير عمل ADK 2.0 الرسومية (محرك رسومي موحد يستبدل قوالبي Sequential/Loop)، وتوافقًا مع MCP SDK 1.x و2.x. بنية ADK 2.0 الآن محرك رسومي حتمي بتوجيه عقد ديناميكي، وTask API رسمية لتفويض المنسق←الوكيل الفرعي، وHITL كبدائيات رسومية أصلية (تغييرات breaking مقابل 1.x في التخزين/مخطط الأحداث؛ دلالات استئناف العقد تغيرت — العقد الفاشلة تُعاد عند الاستئناف، فيجب أن تكون أجسام العقد idempotent). Kotlin ADK 1.0 بلغ GA أيضًا في 9 سبتمبر 2026.

## لماذا يهم ACI
آلية التجاوز التلقائي للموديلات ذات صلة مباشرة بتصميم تجمع LiteLLM الخاص بـ "الخزان (llm)" لدى محمد — يُظهر ADK كيف ينفّذ إطار رئيسي health-check ← failover (مُحفَّز بالأخطاء، قوائم موديلات احتياطية). نمط الرسم الإعلاني بـ YAML + Task API هو أيضًا أقرب نظير سائد لتصميم orchestrator-workers في ACI وقد يُلهم إعادة هيكلة مستقبلية.
