# n8n 3.0.0 بيتا (27 أكتوبر): Docker فقط، عقد مهملة تُزال، ومهلة Code node تنخفض من 5 دقائق إلى دقيقة — خطة ترحيل لا ترقية فورية

## ما الذي تغيّر
- **27 أكتوبر 2026:** أعلنت n8n الإصدار **3.0.0 BETA** (مدونة n8n الرسمية)، مع إصدار مستقر متوقع **مطلع ديسمبر 2026**. الإصدار يركّز على الأساس (موثوقية/استقرار/أمن) لا على ميزات جديدة، ويتضمن تغييرات كاسرة.
- **أهم التغييرات الكاسرة (موثّقة رسميًا):**
  - **Docker أو لا شيء:** الاستضافة الذاتية عبر npm/npx لم تعد مدعومة في 3.0، ولا تُنشر حزمة n8n قابلة للتشغيل على npm. Kubernetes/Helm غير متأثرة.
  - **عقد مهملة تُزال:** Function وFunction Item تصبح Code node؛ وCron وInterval تصبح Schedule Trigger؛ وItem Lists تتفكك إلى Split Out/Aggregate/Sort/Limit؛ وWorkflow Trigger تصبح n8n Trigger؛ وعقد OpenAI القديمة تنتقل إلى العقدة الحالية.
  - **وضع queue:** التنفيذات اليدوية تعمل الآن دائمًا على الـworkers، لا على النسخة الرئيسية.
  - **مهلة Code node الافتراضية:** من 5 دقائق إلى **دقيقة واحدة** (قابلة للضبط عبر `N8N_RUNNERS_TASK_TIMEOUT`).
  - **أمن مشدّد:** قائمة حظر SSRF الافتراضية أكبر، وحدود فك ضغط الأرشيفات الكبيرة أخفض، وحزم المجتمع غير الموثّقة معطّلة افتراضيًا، وبيانات binary في الذاكرة لم تعد خيارًا (`N8N_DEFAULT_BINARY_DATA_MODE=default` غير صالح — اختر filesystem أو S3 أو Azure).
  - **وضع AI Agent v1 يُزال**، وChat Trigger يغيّر صيغة الإطار، وChat Hub معطّل افتراضيًا في 3.0 ومُزال في 4.0.
- **قاعدة حرجة من وثائق الترحيل:** workflow يحتوي عقدًا مُزالة **يفشل عند التشغيل ولا يُفعَّل عند بدء 3.0** — أي أن triggers تتوقف بصمت ما لم يُنفَّذ Migration Report أولًا. الترحيل التلقائي يغطي تغييرات العقد فقط، ويجب اختبار المخرجات قبل النشر.

## لماذا يهم ACI
- نسخة ACI هي **2.43.7** (npm، على localhost) — أي أنها تقع بالضبط في فئة «npm installs stop working» عند 3.0. الترقية إلى 3.x ليست ترقية، بل **ترحيل نشر** (Docker Compose + إعادة اختبار workflows + مراجعة مهلة Code node).
- هذا يكمّل ملف 29 أكتوبر (تنبيهات 28 أكتوبر التي جعلت 2.45.5 مرشح الترقية داخل فرع 2.x): المسار الآمن هو 2.43.7 ← 2.45.5 أولًا، ثم التخطيط لـ3.x في بيئة منفصلة، لا قفزة مباشرة.
- تجربة الـagents المستقلة الجديدة في n8n ما زالت Preview — لا تُبنى عليها مهام ACI الحرجة، وn8n 3.0 لا يحوّل المحرك إلى بديل LangGraph للوكلاء ذوي الحالة المعقدة (تحليل 29 أكتوبر).

## الإجراء: WATCH (وتحضير، على «نفذ» فقط)
1. لا ترقية إلى 3.x في الإنتاج قبل: تشغيل Migration Report على 2.x، وإصلاح العقد المهملة، واختبار الـworkflows في بيئة Docker منفصلة.
2. عند التخطيط: راجع كل مهام Code node الطويلة (مهلة الدقيقة الجديدة) وworkflows الـGmail Trigger.
3. المسار المعتمد يبقى: 2.45.5 كمرشح داخل 2.x في نافذة الصيانة التالية، على «نفذ» من محمد.
