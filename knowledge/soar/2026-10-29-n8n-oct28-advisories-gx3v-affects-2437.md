# n8n — تنبيهات 28 أكتوبر: GHSA-gx3v تؤثر على نسختنا 2.43.7 (إصلاحها 2.45.5+) — وGHSA-9p7v مغطاة أصلًا

## ما الذي تغيّر
- **28 أكتوبر 2026:** نشرت n8n حزمة تنبيهات أمنية عالية الخطورة مع إصدارات إصلاح عبر الفروع: 3.0.1 و2.46.1 و2.45.5.
- **GHSA-gx3v-3x3v-f8r5 — «Insufficient Isolation in Workflow Expression Evaluation»:** مستخدم موثّق لديه صلاحية إنشاء/تعديل workflows يمكنه كسر عزل تقييم التعبيرات (expressions) وتنفيذ كود عشوائي على مضيف n8n. **الإصلاح في: 1.123.89 و2.45.5 و2.46.1 و3.0.1 فقط.** لا يوجد إصلاح 2.43.x لهذا التنبيه — أي أن **نسختنا 2.43.7 غير مغطاة**.
- **GHSA-9p7v-45m2-wxgj — «Deprecated Code Nodes Allow Code Execution in the n8n Main Process»:** عقد Function وFunction Item (vm2 sandbox) وعقدة LangChain Code (تعمل في العملية الرئيسية) تسمح بتنفيذ كود في العملية الرئيسية خارج عزل task runner. **الإصلاح في: 2.42.6 و2.43.3 و2.44.0 و3.0.1** — أي أن **نسختنا 2.43.7 مغطاة أصلًا** (العقد المهملة محظورة افتراضيًا منذ 2.43.3؛ workflows المحفوظة سابقًا بها تستمر بالعمل دون تغيير).
- تنبيهات أخرى في نفس الحزمة (تم مسحها، لا تنطبق مباشرة): إعداد GraphicsMagick غير آمن (GHSA-f2cw-9483-7vcp)، حقن SQL عبر Metadata Filter في عقدة OracleDB Vector Store (GHSA-2x68-96jw-5r6c — لا نستخدم OracleDB)، اختطاف حساب OAuth في تدفق End-User Credential Connect (GHSA-426f-xmcv-g8pg — لا نستخدم هذا التدفق).
- **3.0.1** هو إصلاح فرع 3.0 (بيتا) — لا يغيّر الخطة: stable المتوقع مطلع ديسمبر، والترقية إليه تتطلب Docker أولًا.

## لماذا يهم ACI
- n8n هو طبقة الأوركسترا في ACI (workflow «ACI — Intelligence Mission Trigger» النشط). ثغرة هروب عزل التعبيرات تعني أن أي محرّر workflows موثّق يصبح قادرًا على تنفيذ كود على المضيف.
- **تقييم المخاطر الفعلي لنسختنا:** منخفض نسبيًا رغم التصنيف «عالي» — النسخة تعمل على localhost فقط (غير مكشوفة للإنترنت)، ومحرّرها الوحيد هو محمد (مالك موثوق). لا يوجد مستخدمون آخرون يمكنهم استغلالها، ولا webhook عام يقبل تعبيرات من غير موثّقين. مع ذلك، الثغرة حقيقية ويجب إغلاقها في نافذة الصيانة التالية، لا تجاهلها.

## الإجراء: ADOPT (في نافذة الصيانة، على «نفذ» فقط)
1. **مرشح الترقية الجديد هو 2.45.5** (يحل محل 2.45.3 كمرشح): ترقية npm داخل فرع 2.x، مع نسخة احتياطية أولًا، وتدقيق العقد المهملة، وتشغيل Migration Report (متاح من 2.39).
2. **لا ترقية إلى 3.x** قبل خطة Docker Compose + اختبار في بيئة منفصلة (ترقية 3.x أحادية الاتجاه، لا عودة إلى 2.x إلا بالنسخة الاحتياطية).
3. مؤقتًا حتى الترقية: لا يُمنح أي مستخدم إضافي صلاحية تحرير workflows؛ مراجعة الـworkflows النشطة بحثًا عن تعبيرات تشير إلى خصائص JavaScript غير متوقعة.
