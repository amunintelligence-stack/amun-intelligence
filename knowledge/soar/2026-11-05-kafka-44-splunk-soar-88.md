# Kafka 4.4.0 و Splunk SOAR 8.8.0 — دلتا SOAR/الطوابير 5 نوفمبر

## Kafka 4.4.0: قوائم رسائل ميتة لمجموعات المشاركة؛ 4.3.2 يصلح خطأَي فقدان بيانات محتملين
- **التاريخ:** 4.4.0 صدر 2026-10-22؛ 4.3.2 صدر 2026-10-23.
- **ما الذي تغيّر:** 4.4.0 (25 KIP، 963 commit): قوائم رسائل ميتة (DLQs) لمجموعات المشاركة (KIP-1191) — السجلات تصبح مؤهلة لـ DLQ بعد فشل التسليم؛ مخازن حالة معاملاتية لـ Kafka Streams (`enable.transactional.statestores`)؛ مقاييس منسق مجموعات Yammer مهملة. 4.3.2 (~60 إصلاحًا): مشكلتا فقدان بيانات محتملتان في التخزين المدرّج (الاحتفاظ بالحجم KAFKA-20732؛ اقتطاع فهرس الزمن KAFKA-20979) إضافة إلى تحديثات تبعيات CVE (jackson-databind، lz4-java، log4j، jetty). ملاحظة: قوائم Kafka (مجموعات المشاركة) أصبحت جاهزة للإنتاج في 4.2 (فبراير 2026)، لكن عملاء غير Java (منهم Python confluent-kafka 2.15.0) ما زالوا يشحنون مستهلك المشاركة كمعاينة — ليس للإنتاج في Python.
- **لماذا يهم ACI:** ACI لا يشغّل Kafka (المهام تستخدم n8n + FastAPI + Postgres). ذو صلة فقط إن بُني طابور مهام دائم يومًا: Kafka 4.4 يجعل Kafka طابورًا موثوقًا (DLQs)، لكن حالة معاينة عميل Python تحظر ذلك المسار لمكدس Python في ACI اليوم؛ `FOR UPDATE SKIP LOCKED` في Postgres يبقى الطابور العملي.
- **المصادر:** https://kafka.apache.org/community/downloads/ (4.4.0 في 22 أكتوبر؛ 4.3.2 في 23 أكتوبر) — https://medium.com/@ascendrixtech/apache-kafka-4-4-8193f550f496
- **الإجراء: watch.** لا إضافة سجل (ليست أداة جديدة).
