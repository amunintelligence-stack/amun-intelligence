# ToucanDB v2.0.0 (2026-09-19): محرك متجهات مدمج دائم بمسار مصدر SQLite وخط أنابيب RAG مدمج

## ماذا تغيّر
- إصدار رئيسي (2026-09-19) حوّل المشروع إلى **محرك متجهات مدمج (embedded) دائم بدون خادم**:
  - مصدر الحقيقة: SQLite مع WAL وتحديثات/حذف دفعية ذرية، ولقطات FAISS قابلة لإعادة البناء مع فحص الجيل والمخطط، ونسخ احتياطية قابلة للفتح مباشرة.
  - **RAG من الدرجة الأولى**: `RAGStore` بدون تبعيات، تجزئة حتمية (deterministic chunking)، تقليم أسماء النطاقات (namespace pruning)، استرجاع مُنسب للمصادر (attributed retrieval)، وخط أنابيب `RAGPipeline` قابل للمراقبة مع آثار المراحل ومقاييس الاسترجاع.
  - **بحث مفلتر دقيق**: البحث المفلتر بالبيانات الوصفية لم يعد يُسقط متجهات مطابقة على HNSW — الفلتر غير المُرضى يحصل على تمريرة دقيقة واحدة.
  - حذف tombstones داخل FAISS فلا ينمو زمن HNSW مع الحذف؛ تحميل السجلات دفعيًا.
  - تبعيات أساسية خفيفة فقط: NumPy وFAISS CPU وCryptography وPydantic وMessagePack وLZ4؛ مزودا التضمين (Sentence Transformers / OpenAI) إضافات اختيارية؛ Python 3.10–3.14.
- تغييرات كاسرة: الحد الأدنى Python 3.10؛ مزودا التضمين أصبحا extras منفصلة؛ دليل ترحيل مطلوب لفتح قواعد بيانات 1.x.

## لماذا يهم ACI
- يطابق فلسفة "البدائل الناجية من المسح" (wipe-survivor) المثبتة في ACI: ملف واحد قائم على SQLite يعيش في `~/workspace`، بدون خدمة خارجية تُفقد عند إعادة تدوير الـ VM — نفس النمط الذي أنقذ الـ DB بعد مسح PostgreSQL.
- بديل مدمج وخفيف للنظر فيه مستقبلًا لذاكرة الوكيل/المهمات بدل تثبيت Qdrant منفصل — لكن Qdrant يظل الهدف للبحث الإنتاجي (فلترة payload غنية، بحث هجين، تعدد مستأجرين).
