# FalkorDB-rs 0.11.0 + تكلفة GraphRAG مقابل Vector RAG — تحديث 28 أكتوبر 2026

**التاريخ:** 2026-10-28 | **الفئة:** graph | **الحالة:** إصدار عميل + تحليل تكلفة، لا تغيير على محرك ACI (networkx)

## ما الذي تغيّر
- **FalkorDB-rs 0.11.0** صدر في **26 أكتوبر 2026** (crates.io/lib.rs): العميل الرسمي بلغة Rust لـ FalkorDB — API واحد للعميل المتزامن وغير المتزامن (tokio)، معاملات مكتوبة الأنواع، دفعات، خادم مضمّن، TLS، إعادة محاولة تلقائية، وتتبّع متوافق مع OpenTelemetry. الإصدار كسر توافقًا سابقًا (10 إصدارات كاسرة من أصل 33) — أي ترقية عميل تتطلب مراجعة التغييرات الكاسرة.
- **نقاش GraphRAG مقابل Vector RAG (16 أكتوبر 2026):** الفارق في تكلفة الرموز (tokens) المُشار إليه — Microsoft GraphRAG أعلى بـ **16.6x** من LightRAG — يذكّر بأن البنية تتراكم تكلفتها سريعًا مع الطبقات. التعليق يضيف طبقة أدنى: قاعدة الرسم نفسها؛ FalkorDB (داخل الذاكرة، Redis + GraphBLAS) يُعلن اجتيازًا أسرع 10x–100x من Neo4j في الاستعلامات متعددة القفزات، وخيارات متعددة النماذج (ArangoDB/ArcadeDB) تتجنب ربط مخزن متجهات منفصل بالرسم.
- مشاريع Graph Hacks (أكتوبر 2026) مثل RepoBrain و"company brain" تبني رسوم معرفة في FalkorDB من GitHub — نمط قابل للاستعارة: طبقات كود + تاريخ PR + نية (Issue) + ذاكرة في رسم واحد، وعزل المستأجرين برسوم منفصلة داخل نسخة واحدة.

## لماذا يهم ACI
- رسم ACI ما زال networkx داخل الذاكرة — لا مبرر الليلة لتغيير المحرك. لكن عند نمو الرسم، المرشّح FalkorDB 6.0.3 يبقى المثبّت (ليلة 23 أكتوبر)، وعميل Rust الجديد لا يغيّر شيئًا لأن ACI بايثون.
- درس التكلفة عملي مباشرة: أي GraphRAG مستقبلي في ACI يجب أن يُقيَّم بميزانية رموز لكل استعلام، لا بدقة استرجاع فقط — الرسم الكامل لكل استعلام هو ما يفجّر التكلفة 16.6x.

## الإجراء: WATCH
- لا تغيير على تثبيت FalkorDB 6.0.3. عند تصميم أي طبقة GraphRAG مستقبلية: إسقاط فرعي لكل مهمة (per-mission subgraph projection) + حدّ قفزات، وقياس تكلفة الرموز قبل التبني.
