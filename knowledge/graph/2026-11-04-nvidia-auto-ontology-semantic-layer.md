# NVIDIA Auto Ontology: طبقة دلالية حاكمة فوق قواعد البيانات (3 نوفمبر 2026)

## ما الجديد

- ظهر مشروع NVIDIA المسمى Auto Ontology على Hacker News صباح 3 نوفمبر 2026، وبلغ مستودعه على GitHub حوالي 1,100 نجمة و112 fork عند قراءته في ذلك اليوم، وفق تغطية ثانوية (explainx.ai) تلخّص ملف README ووثائق المشروع. لم تُتحقق هذه الليلة من المستودع الأصلي مباشرة، لذا تُعامل التفاصيل أدناه على أنها منقولة عن تلك التغطية حتى مراجعة README الأصلي.
- الفكرة: إطار عمل بترخيص Apache-2.0 يبني طبقة معنى أعمال (ontology وsemantic catalog) فوق بيانات المؤسسة ويقدّمها للوكلاء عبر MCP وCLI وAPI، بحجة أن "reliability gates agentic analytics: a revenue metric answered faster is worth nothing if the number is wrong" — أي أن سرعة الإجابة لا قيمة لها إذا كان الرقم خاطئًا. الوظائف الخمس المعلنة: Discover (توليد أنطولوجيات من البيانات الوصفية وبناء رسوم معرفية جاهزة للذكاء الاصطناعي)، وGround (توحيد تعريفات المقاييس والكيانات والعلاقات عبر الأنظمة)، وValidate (التحقق من الاستعلامات المولّدة مقابل تعريفات معتمدة وإعادة النسب provenance)، وExpose (التقديم عبر MCP/CLI/API)، وLearn (طيّ التصحيحات المعتمدة في الأنطولوجيا).
- البنية: واجهة Next.js 16 على المنفذ 3000، وخلفية FastAPI على Python 3.12+ مع LangChain على المنفذ 3001، وعامل استيعاب FastAPI على المنفذ 3002، وPostgres مع pgvector على المنفذ 5432 لتخزين بيانات التطبيق والكتالوج والأنطولوجيا والمتجهات معًا. مصادر البيانات المدعومة: Databricks وPostgres وSnowflake وDuckDB. النشر عبر Docker Compose محليًا أو Helm chart لـ Kubernetes. النماذج الافتراضية عبر NVIDIA NIM: `nvidia/nemotron-3-nano-30b-a3b` للغة، و`nvidia/nemotron-3-embed-1b` للتضمين، و`nvidia/llama-nemotron-rerank-vl-1b-v2` لإعادة الترتيب، مع إمكانية توجيه أي دور إلى أي نقطة نهاية متوافقة مع OpenAI.
- خادم MCP للقراءة فقط عمدًا: لا توجد أداة لتصفح قواعد البيانات أو المخططات أو الأعمدة الخام، لأن المؤلفين يريدون أن يصل الوكيل إلى البيانات عبر الطبقة الدلالية لا عبر الجداول الخام. الأدوات تشمل `ask_question` (سؤال بلغة طبيعية يُعيد الإجابة وSQL والصفوف)، و`check_answerable` و`check_readiness` (فحص ما إذا كانت الطبقة الدلالية تغطي السؤال وما إذا كان النشر قادرًا على الإجابة أصلًا)، و`search_terms` و`get_term` و`get_term_columns` و`get_term_sql_attributes` و`describe_table`. جلسات MCP ترث صلاحيات المستخدم الموقّع، ولا تحمل بيانات اعتماد قواعد بيانات خاصة بها.
- حدود معلنة مهمة: ثقيل التشغيل (أربع خدمات مع Postgres)؛ الاتصالات المضافة عبر واجهة الويب تحتفظ بكائن الاتصال كاملًا، بما فيه كلمة المرور، دون تشفير في صف الكتالوج ما لم يُضبط Vault بالكامل، والإعداد الجزئي لـ Vault يُتجاهل مع تحذير ويعود إلى النص العادي؛ لا توجد أرقام دقة معلنة (يشير README إلى مستودع تقييم منفصل دون درجات)؛ لا تُقبل مساهمات خارجية ("Issues, pull requests, and patches submitted from outside the Auto Ontology maintainer team will not be reviewed or merged")؛ الإجابات بطيئة (عشرات الثواني للسؤال الواحد)؛ وحزمة MCP عبر `uvx` غير مكتملة بعد (تعمل من المستودع مباشرة، وستعمل بالصيغة العادية "once the package is published to PyPI")، مع ملاحظة داخلية قديمة تفيد بأن المشروع "NVIDIA-internal today".

## لماذا يهم ACI

- الدرس القابل للنقل إلى ACI أقوى من الأداة نفسها: وكلاء ACI يستعلمون كيانات وعلاقات، وتعريف واحد غامض (مثل "إيرادات" أو "شركة تابعة") يمكن أن يفسد مهمة كاملة. نمط "طبقة دلالية معتمدة" — مسرد مصطلحات يربط كل مصطلح بالأعمدة وSQL الذي يعرّفه، وأدوات تقرأ المعنى لا الجداول الخام — يصلح كطبقة حوكمة خفيفة فوق رسم networkx الحالي ولقطات Postgres، دون الحاجة إلى تشغيل حزمة NVIDIA الثقيلة.
- نقطتان أمنيتان تستحقان التثبيت كقاعدة في ACI: أولًا، عدم تخزين بيانات اعتماد اتصالات دون تشفير أبدًا (تحذير Vault في Auto Ontology مثال حي على فشل صامت يعود إلى النص العادي)؛ وثانيًا، أن أدوات الوكيل يجب أن ترث صلاحيات المستخدم، لا أن تحمل صلاحيات أوسع من صاحب الجلسة.
- لا يناسب ACI تبنّي Auto Ontology نفسها الآن: ثقيلة، بطيئة، بلا أرقام دقة، بلا مساهمات خارجية، ومرتبطة بمنظومة NVIDIA NIM، بينما رسم ACI ما زال خفيفًا ولم يبلغ عتبة تستدعي طبقة أنطولوجيا كاملة.
