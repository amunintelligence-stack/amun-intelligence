# Graph — Neo4j 2026.10, falkordb-rs 0.11.0, FalkorDB 4.22.3, GraphRAG engine critique

## What changed
- **Neo4j 2026.10** (23 Oct 2026; 2026.10.1 patch): current supported line; 2026.09 support ended 20 Oct 2026 (endoflife.date, updated 3 Nov 2026). Confirms the monthly-cadence line tracked since 2026.09.
- **falkordb-rs 0.11.0** (26 Oct 2026): official Rust client — blocking + async tokio clients, typed results, batching, embedded server, TLS, retries, OpenTelemetry tracing. Client-only release; no engine change, no ACI impact (graph stays networkx).
- **FalkorDB 4.22.3** (28 Oct 2026): RediSearch index fix (present since 4.20.0) + GraphBLAS 10.5.2-beta2. The 4.x line is still being patched — but the standing rule stands: **never deploy 4.x** (no supported 4.x→6.x path until 6.2; 6.0.3 remains the candidate pin).
- **GraphRAG engine critique** (dev.to, Oct 2026): Neo4j-as-GraphRAG mismatch argument — analyst-dashboard heritage vs single-digit-ms multi-hop agent retrieval; shortlist for agent workloads: ArcadeDB (multi-model + built-in MCP server), FalkorDB (in-memory, 10–100x traversal claims), ArangoDB (four models, one engine), Memgraph (C++ in-memory, Bolt-compatible, Kafka-friendly), TigerGraph (scale tier). Vendor/analyst claims, not benchmarks — treat as a shortlist, not evidence.
- **Neo4j Context Engine** pattern (GraphSummit, tracked since 25 Oct) continues to be the ontology-front-door reference for ACI graph design.

## Why it matters for ACI
- No engine change: networkx + Postgres snapshots remain the graph layer; FalkorDB 6.0.3 stays the candidate pin for the day the graph outgrows networkx. The critique's useful takeaway is architectural, not a product pick: agent retrieval latency (multi-hop + vector fusion, hundreds of queries/min) is a different workload from analyst Cypher — ACI's future graph upgrade must be benchmarked on that workload, not dashboard queries.
- ArcadeDB's built-in MCP server is a pattern worth copying if ACI ever exposes its graph over MCP (read-only tools first, as with Memgraph's MCP_READ_ONLY flag).
