# FastMCP v4.1.2 "License to Deny" — auth hardening + SEP-2640 Skills foundation

## What changed
FastMCP released **v4.1.2** on 2026-10-20 with two security fixes: (1) component authorization now applies **after** tool transforms, so a denied resource can no longer fall through to a matching template and get served anyway; (2) `ClientCredentialsOAuthProvider` and `PrivateKeyJWTOAuthProvider` now **bind OAuth client credentials to a configured issuer**, including cached-token renewal flows. Critically, the changelog states upgrading alone is insufficient: users of those providers **must set `issuer`** to enable the protection — the same three-part remediation pattern as the October MCP SDK OAuth CVEs (CVE-2026-104850 / GHSA-qx49-fqc8-xw99). It also adds the **SEP-2640 Skills extension foundation** plus experimental skill discovery in `SkillsDirectoryProvider`. No breaking changes; 4.x users encouraged to upgrade.

## Why it matters for ACI
ACI's MCP plans run on FastMCP (registry already pins >=4.1.1). The denied-resource template fallback is an authorization bypass class ACI servers could inherit silently; the issuer-binding fix closes the OAuth credential-leak class directly in the framework. The Skills foundation means ACI analyst playbooks/personas can eventually be served as MCP-native skills (`skill://` URIs) instead of ad-hoc prompt injection.
