# MCP كجسر لانتشار حقن الأوامر بين الوكلاء داخل المؤسسات

- التاريخ: 2026-10-11 | الفئة: mcp | الإجراء: **مراقبة**

## ما الذي تغيّر
تقرير صحفي (6 أكتوبر 2026) يوثّق نمط هجوم هيكلي: MCP لا يقرّب الأدوات فقط بل أصبح **قناة لانتقال التعليمات الخبيثة من وكيل داخلي إلى آخر** متجاوزًا الحواجز المعتادة. خلال خمسة أشهر، أقرّت Google وأربع مؤسسات أخرى بثغرات سمحت لوكيل واحد داخل الشبكة بنشر تعليمات ضارة عبر سلسلة الوكلاء. النمط هو حقن أوامر (prompt injection) لكنه يستهدف **الوكيل** لا النموذج اللغوي مباشرة: بمجرد أن يقبل وكيل ضعيف الحماية (ترجمة، تحليل بيانات) التعليمات، يُمرّرها كـ«زميل داخلي موثوق» فيرفضها الوكلاء اللاحقون أقل.

## لماذا يهم ACI
معمارية ACI متعددة الوكلاء (منسّق + وكلاء فرعيون عبر الجسر) هي بالضبط هذا النمط: وكيل يثق بزميله. إذا وكّلنا مهمة استخبارات تتضمن قراءة محتوى خارجي غير موثوق (صفحات، تقارير) ثم تمريره لوكيل آخر، يمكن لتعليمات مزروعة في المحتوى أن تنتقل عبر السلسلة. القاعدة: عامل أي محتوى قادم من وكيل/أداة كمدخل غير موثوق، وافصل صلاحيات الوكلاء (وكيل القراءة لا يملك صلاحية الكتابة/التنفيذ).
