## 1. FastMCP v4.2.0 «Mad Skills» — صدر اليوم، 2026-11-13 17:07 UTC (رفع PyPI 17:08:59Z)

- **ما الذي تغيّر:** إصدار رئيسي. المهارات (Skills) تصبح قدرة خادم من الدرجة الأولى: `Skill` الآن كائن تأليف محايد التخزين (الاسم، الوصف، التعليمات، الملفات)، يُقدَّم عبر `SkillCatalogProvider`/`SkillsDirectoryProvider` كموارد عادية، إضافة إلى `skills/list` مع بيان مُجزَّأ للعملاء الناطقين بامتداد SEP-2640 Skills التجريبي. `Client.read_skill()` يتحقق من حجم/بصمة كل ملف؛ `to_directory()` يثبّت مهارة في مجلد مهارات أي وكيل. مساحة اسم المهارات تحت التركيبات، تمر عبر الوكلاء (`skills=True`)، تُسرد عبر `ClientGroup`، وتحترم `AuthMiddleware`. أيضًا: تبعيات `Annotated[...]`، وسيطات أدوات مملوكة للتبعية `CallArgument`، ومُحقِّق مصادقة جديد `KeystoneTokenVerifier`. **كاسر:** يتطلب Python **3.11+**؛ **API مهارات 4.1 مهمل ويُزال في 4.3** (`fastmcp.server.providers.skills` و`fastmcp.utilities.skills` ما زالا يعملان بتحذيرات؛ جدول ترحيل في وثائق المهارات؛ النموذج السلكي أُعيد تسميته `MCPSkill`).
- **لماذا يهم ACI:** هذا هو الإصدار الذي يجعل كتيبات/شخصيات محلل ACI قابلة للتقديم كمهارات أصلية في MCP مع تحقق من السلامة — الاتجاه نفسه الذي أُشير إليه في ملاحظتي 20 أكتوبر (4.1.2) و18 أكتوبر. لكنه إصدار رئيسي في اليوم نفسه مع تغييرات كاسرة؛ ثبيت السجل الحالي `>=4.1.6`.
- **المصادر:** https://github.com/PrefectHQ/fastmcp/releases/tag/v4.2.0 (2026-11-13)؛ https://pypi.org/project/fastmcp/ (4.2.0)؛ https://gofastmcp.com/docs/servers/skills (جدول الترحيل)
- **الإجراء: adopt (مرحلي)** — ارفع أرضية السجل إلى `>=4.1.8` الآن (انظر #3)؛ قيّم 4.2.0 في التطوير مقابل جدول الترحيل قبل نقل الثبيت، ولا تبنِ على API مهارات 4.1 المهمل.

## 5. VS Code 1.145.3 — 2026-11-10 (3 ثغرات MCP + 1 ثغرة وضع وكيل)

- **ما الذي تغيّر:** أصلحت Microsoft أربعة عيوب، ثلاثة في عميل MCP: **CVE-2026-120779 (CVSS 9.6)** — إشعار استنباط من خادم MCP عدائي يُعرض كرابط أمر قابل للنقر، فتنقرة واحدة تشغّل كودًا؛ **CVE-2026-114171 (CVSS 8.8)** — رابط `vscode:mcp/install` مصمم يحمل مدخلات مدعومة بأوامر لم تُظهرها المعاينة، فالموافقة على التثبيت تشغّل أوامر يختارها المهاجم؛ **CVE-2026-119983** — نقاط SSE قديمة؛ إضافة إلى **CVE-2026-120782** (وضع الوكيل: صياغة أوامر محلية في رسائل الوكيل قد تُشغَّل دون موافقة الطرفية). تؤثر على VS Code ≤1.145.2، كل المنصات. **لا استغلال مُبلَّغ عنه**؛ Microsoft تقيّم الاستغلال أقل احتمالًا؛ لا CVE منها في CISA KEV. لم ينشر أي بائع شوكة VS Code بيانًا حتى 12 نوفمبر.

- **المصادر:** https://github.com/microsoft/vscode (الاستشارات GHSA-66hq-jw93-462h وما يليها، 2026-11-10)؛ https://www.beri.net/article/vs-code-mcp-rce-cve-2026-120779-cve-2026-114171-elicitation-install-link-1-145-3-patch-mcp-server-allowlist ؛ https://theinjection.dev/items/microsoft-vscode-1-145-3-mcp-agent-cves/
- **الإجراء: adopt** — حدّث VS Code إلى ≥1.145.3 على كل أجهزة التطوير؛ لا توافق على روابط `vscode:mcp/install` من مصادر غير موثوقة. **ليس تنبيهًا حرجًا للدردشة**: التصحيح موجود، ولا استغلال، ولا خوادم MCP تعمل في مكدّس ACI اليوم.

- **ما الذي تغيّر (بحث، لا CVE):** (أ) **Log-To-Leak** — هجمات حقن مطالبات عبر أوصاف أدوات مسمومة بلغت **62.64–100% نجاح هجوم** بينما إكمال المهمة المستهدفة بالكاد تحرك في 16 من 18 زوجًا مختبرًا (تسريب خفي عبر السجلات)؛ (ب) **دراسة MCP-FSD على 21,097 خادمًا** من تسعة سجلات: **787 من 4,806 خادمًا مُفرَزًا (16.4%) كانت لها قدرات نظام ملفات رغم تصنيفات غير نظام ملفات**، و150 مؤكدة ضعيفة تحت سياسات صندوق رمل مختبرة، والكشف المنسق أنتج **13 استشارة أمنية منها CVEان في خادم Git MCP الخاص بـ Anthropic**؛ (ج) تسريب بيئة `server-everything` عبر CORS بعلامة بدل + `get-env` (أُصلح في 2.0.1)؛ هجوم إعادة ربط DNS على نقل SSE غير مصادَق.
- **لماذا يهم ACI:** يكمّم قاعدتين في وضع ACI أصلًا: أوصاف الأدوات مدخل غير موثوق (يعزز CVE-2026-54140، 12 نوفمبر)، والفئة المعلنة للخادم لا تخبرك بشيء عما يستطيع قراءته — إدراج السجل ≠ تدقيق. يدعم مباشرة سياسة «اقرأ أولًا، واكتب فقط بموافقة موقَّعة».
- **المصادر:** https://adversa.ai/blog/top-mcp-security-resources-november-2026/ (نوفمبر 2026)
- **الإجراء: watch** — سياق بحثي؛ لا اعتماد. استشهد به في قائمة فحص أمان MCP.
