## 1. FastMCP 4.2.2 (18 نوفمبر 2026) — إصلاح اكتشاف المهارات لعملاء الأدوات فقط

- **ما الذي تغيّر:** صدر **FastMCP v4.2.2** في 18 نوفمبر: إضافة تحويل خادم مثل `ResourcesAsTools` كانت تجعل `skills/list` تعود فارغة رغم بقاء ملفات `skill://` قابلة للقراءة؛ الآن تُدرَج المهارات متى كانت ملفاتها تُقدَّم فعلًا.
- **لماذا يهم ACI:**‏ أي خادم MCP نبنيه حول أدوات ACI ويعرّض مهارات عبر تحويلات الموارد كان سيخفي مهاراته عن العملاء — الإصلاح يهم نمط «الأدوات + المهارات» الذي ننسخه من GraphIQ/Memgraph. لا FastMCP في مكدّس ACI حاليًا.
- **المصادر:** GitHub API (jlowin/fastmcp releases/tags/v4.2.2، فُحص 19 نوفمبر 2026)
- **الإجراء: watch** — لا اعتماد؛ سجّل الإصلاح كمرجع عند بناء/تقييم أي خادم MCP مستقبلي.

## 2. MCP Java SDK 2.2.0 (16 نوفمبر) — دعم المواصفة بلا جلسات (2026-07-28)

- **ما الذي تغيّر:** صدر **MCP Java SDK 2.2.0** في 16 نوفمبر داعمًا المواصفة **2026-07-28**: بلا مصافحة `initialize`، وبلا جلسات بروتوكول، وكل طلب يحمل سياقه — مع واجهة برمجية حديثة منفصلة (`io.modelcontextprotocol.modern.*`) والقديمة بلا تغيير. تحذير رسمي: الواجهة الحديثة قد تتغير في إصدارات فرعية قبل 3.0.
- **لماذا يهم ACI:**‏ يؤكد أن منظومة SDKs الرسمية كلها (TypeScript 2.x، Python 2.3.0، Go، C#، والآن Java) تتجه إلى المواصفة بلا جلسات. أي خادم MCP نبنيه لاحقًا يُبنى على 2026-07-28 مباشرة، بلا كود جلسات.
- **المصادر:** https://dev.to/nicholas1991/mcp-java-sdk-220-released-removing-the-session-handshake-3h6 (18 نوفمبر 2026)؛ https://www.linkedin.com/pulse/stateless-mcp-how-build-server-scales-behind-any-load-attupurath-74lxc (11 نوفمبر 2026)
- **الإجراء: watch** — لا تغيير في خطة MCP؛ المواصفة الحالية 2026-07-28 هي الأساس لأي خادم مستقبلي.
