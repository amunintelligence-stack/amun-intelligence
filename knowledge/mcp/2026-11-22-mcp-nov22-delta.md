# دلتا MCP — امتداد Events يصل إلى Final؛ GitHub MCP Server 2.2.0 بمهارات مُصفّاة؛ Cognito يدعم CIMD (22 نوفمبر 2026)

## 1. SEP-3415: امتداد Events يصل إلى Final ويُسجَّل في الوثائق (أسبوع 20 نوفمبر 2026)

- **ما الذي تغيّر:** سُجّل امتداد Events (`io.modelcontextprotocol/events`) رسميًا في وثائق MCP بعد وصول SEP-3415 إلى حالة Final (الالتزام `bbc31f8`، PR رقم `#3568` في مستودع `modelcontextprotocol/modelcontextprotocol`). الامتداد في حالة Beta ويصونه فريق عمل Tasks and Events. يتيح للعميل الاشتراك في أحداث تصدر من نظام خارجي — رسالة جديدة، دفع إلى مستودع، حادث إنتاج — فيتفاعل الوكيل دون أن يكون المستخدم حاضرًا.
- **كيف يعمل:** تفاوض على القدرات عبر `server/discover`، ثم `events/list` لاكتشاف أنواع الأحداث (اسم، `inputSchema` لوسائط الاشتراك، `payloadSchema` للبيانات، أوضاع التسليم)، ثم الاشتراك بإحدى ثلاث طرق: Poll (`events/poll`)، أو Push (`events/stream`)، أو Webhook (`events/subscribe` بتوقيع HMAC وفق Standard Webhooks وروابط `https` فقط). مؤشرات (cursors) تتيح الاستئناف بعد انقطاع مع إشارة `truncated: true` عند وجود فجوة، وضمان تسليم «مرة واحدة على الأقل» عندما يكون المصدر دائمًا.
- **لماذا يهم ACI:** هذا هو نمط «المهمة تُطلَق بحدث» الذي تحتاجه منصة استخبارات الشركات: مراقبة مصدر (مستودع، قناة، نظام حوادث) وإيقاظ وكيل عند وقوع حدث بدل الاستطلاع الدوري — يطابق مباشرة نمط مشغّل مهمة ACI وwebhooks في n8n، لكن داخل بروتوكول MCP نفسه. النموذج الأمني في المواصفة نفسها يحذّر أن حمولات الأحداث بيانات غير موثوقة قد تحمل حقنًا للموجهات، وأن استلام حدث لا يمنح الوكيل إذنًا بالتصرف — نفس مبدأ الحارس (guard) في ACI.
- **المصادر:** https://github.com/modelcontextprotocol/modelcontextprotocol/commit/bbc31f8ded5762eae4df115b93942f5e71c8b3a7 (أسبوع 20 نوفمبر 2026)؛ https://library.mikesailab.com/news/ai-news/mcp-news/november-2026/2026-11-20/
- **الإجراء: watch** — لا اعتماد الآن (الامتداد Beta ولا تطبيق مرجعي في SDKs من الفئة الأولى بعد)؛ أضِفه إلى خطة تصميم مشغّل الأحداث المستقبلي في ACI.

## 2. GitHub MCP Server 2.2.0 «The one with Skills» (16 نوفمبر 2026)

- **ما الذي تغيّر:** الإصدار 2.2.0 (تحقق عبر GitHub API في 22 نوفمبر 2026): يستبدل تعليمات الخادم بمهارات MCP مُصفّاة (`feat(skills)`، PR رقم `#3685`)؛ يضيف إخفاءً اختياريًا للأسرار في أدوات تنبيهات فحص الأسرار (PR رقم `#3838`)؛ يضيف أدوات أتمتة وكلاء عامة (PR رقم `#3719`)؛ ويصلح نتائج إكمال فارغة غير خالية (non-nil) وتجاوز سعة أخطاء التحقق.
- **لماذا يهم ACI:** تأكيد ثانٍ مستقل على أن «المهارات عبر MCP» (SEP-2640) أصبحت نمط التغليف السائد — بعد FastMCP 4.2.0 يأتي الآن خادم GitHub الرسمي بنفس الاتجاه؛ هذا يقوّي خيار تغليف شخصيات/مسرحيات المحلل في ACI كمهارات تُخدَم من الخادم. إخفاء الأسرار في أدوات الفحص يطابق قاعدة ACI في عدم تسريب الأسرار في المخرجات.
- **المصادر:** https://github.com/github/github-mcp-server/releases/tag/v2.2.0 (16 نوفمبر 2026)؛ https://library.mikesailab.com/news/ai-news/mcp-news/november-2026/2026-11-20/
- **الإجراء: watch** — راقب نضج دعم المهارات عبر العملاء قبل أي اعتماد في ACI؛ لا تغيير في التثبيتات الحالية.

## 3. Amazon Cognito يدعم مستندات بيانات هوية العميل CIMD (19 نوفمبر 2026)

- **ما الذي تغيّر:** أعلنت AWS أن Amazon Cognito يدعم الآن مستندات Client ID Metadata Documents (CIMD): يستخدم العميل رابط `https` كهوية له وينشر مستند JSON للبيانات الوصفية على ذلك الرابط، فيتحقق Cognito منه عند بدء تسجيل الدخول — دون تسجيل app client منفصل لكل عميل MCP أو وكيل ذكاء اصطناعي. سياسات CIMD (حتى 10 لكل user pool) تربط أنماط الروابط بـapp client قائم، وتُمنح فقط النطاقات وأنواع المنح التي يسمح بها الطرفان معًا. عملاء عامون فقط، بلا `client_credentials`. متاح على خطتي Essentials وPlus في كل المناطق.
- **لماذا يهم ACI:** لو نُشرت خوادم MCP الخاصة بـACI خلف Cognito مستقبلًا، يزول احتكاك تسجيل عميل لكل مساعد خارجي — لكن ACI يعمل محليًا حاليًا ولا يعرّض خوادم MCP علنًا، فلا أثر مباشر. ملاحظة أمنية: نموذج «العميل يعرّف نفسه برابط» يعني أن سياسات القبول (URL patterns) تصبح هي خط الدفاع — أي خطأ فيها يفتح الباب لعملاء غير مرغوبين.
- **المصادر:** https://aws.amazon.com/about-aws/whats-new/2026/11/cognito-client-id-metadata-documents/ (19 نوفمبر 2026)؛ https://www.ajayk.sh/blog/mcp-changelog-tracker/ (فُحص 20 نوفمبر 2026)
- **الإجراء: watch** — مرجع تصميمي فقط؛ لا اعتماد حتى يُتخذ قرار نشر MCP علنًا.

## 4. ملاحظة أمنية: CVE-2026-115563 دخل قاعدة بيانات استشارات GitHub (19 نوفمبر 2026)

- **ما الذي تغيّر:** راجعت GitHub الاستشارة الأمنية لعميل OAuth في Python SDK (CVE-2026-115563، أُصلحت في 1.30.0 و2.2.0 في سبتمبر) وأدخلتها قاعدة بيانات الاستشارات، فبدأت تنبيهات Dependabot هذا الأسبوع.
- **لماذا يهم ACI:** لا ثغرة جديدة — الإصلاح قديم (سبتمبر) والتثبيت المرجعي في ACI هو Python SDK ‏2.3.0‏، أي أعلى من النسخة المصححة؛ لا أثر. الفائدة: تأكيد أن تنبيهات Dependabot ستلتقط أي تثبيت قديم متبقٍّ في بيئات التطوير.
- **المصادر:** https://www.ajayk.sh/blog/mcp-changelog-tracker/ (فُحص 20 نوفمبر 2026)
- **الإجراء: ignore** — لا إجراء، مع التحقق الروتيني من عدم وجود تثبيتات Python SDK أقدم من 2.2.0 في بيئة ACI.
