# Apify MCP Server 0.18.0–0.18.2 — broader API access, safer tool execution

**Date:** 2026-10-16 (releases 2026-10-13 to 2026-10-15)
**Source:** https://undercodenews.com/apify-mcp-server-just-got-a-major-upgrade-more-api-access-safer-tool-execution-and-smarter-actor-management-video/ (secondary — release-notes summary; 0.18.2 listed without accompanying notes)

## What changed
- **0.18.0** expanded API integration: new tools let AI agents search the Apify API, retrieve details, and read information through MCP; added **`apify-api-write`**, enabling calls to Apify API write methods (beyond discovery/reading).
- Security-oriented changes in 0.18.0 target sensitive API operations and aim to make tool execution more predictable; Actor management improved.
- 0.18.1 and 0.18.2 followed within days; 0.18.2 appears in the release list without notes.

## Why it matters for ACI
Apify is the scraping/Actor platform behind many OSINT data-collection flows (social, web, SERP Actors). An MCP server that exposes Apify to agents means ACI missions could drive scrapers through a standard tool interface instead of bespoke API code. The `apify-api-write` addition is the sharp edge: write-capable MCP tools must be allow-listed per mission and never enabled by default — an agent with write access to a scraping platform can start paid runs, modify Actors, and burn budget. The rapid 0.18.x cadence also means: pin versions, read each release's notes before upgrading.

## Action
**Watch.** When ACI needs agent-driven scraping, evaluate Apify MCP with write tools disabled by default and a per-mission allow-list. Do not enable `apify-api-write` without human approval gating.
