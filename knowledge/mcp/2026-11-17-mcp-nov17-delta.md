# دلتا MCP — دفعة ثغرات 16 نوفمبر: 4 خوادم (منها Kubeshark 7.2)؛ وmcp-server-git 7.8 في 11 نوفمبر (17 نوفمبر 2026)

## ⭐ 1. دفعة ثغرات خوادم MCP في 16 نوفمبر 2026 — أربعة إصلاحات، كلها مصححة

- **ما الذي تغيّر:** نُشرت في **16 نوفمبر 2026** أربع استشارات رسمية لخوادم MCP (نشرة AWS 2026-185 وغيرها)، **كلها مصححة**:
  - **awslabs.timestream-for-influxdb-mcp-server — CVE-2026-126681 (CVSS 5.5 متوسط):** سوء معالجة إعدادات الاتصال يتيح لمهاجم (عبر حقن موجّه) الحصول على رمز InfluxDB API المُهيأ على الخادم بإرساله إلى نقطة نهاية مصممة عبر URL في سياق عميل MCP. **الإصلاح: 0.0.19** (من 0.0.12). الاستشارة: GHSA-2f9r-g4f3-wc2j.
  - **awslabs.aws-pricing-mcp-server — GHSA-mqm3-w68j-75mw (متوسط):** أداة توليد تقرير التكلفة قبل **1.0.31** قد تسمح لفاعل يؤثر على وكيل MCP بكتابة محتوى خارج دليل الإخراج المقصود — والأخطر أن الأداة كانت موسومة `readOnlyHint` فعملاء الموافقة التلقائية شغّلوها دون تأكيد. **الإصلاح: 1.0.31** (يحصر `output_file` في دليل أساس، يرفض اجتياز المسار، ويصحح الوسم إلى False). مستخدمو الحزمة المهملة `awslabs.cost-analysis-mcp-server` عليهم الترحيل.
  - **Kubeshark MCP — CVE-2026-129235 (CVSS 5.3 متوسط) + CVE-2026-129236 (CVSS 7.2 عالٍ):** الأولى: أداة `download_file` تكتب بايتات مُجلَبة إلى مسار وجهة غير متحقق منه (كتابة ملف عشوائي — مثل `~/.ssh/authorized_keys`). الثانية: أداة `start_kubeshark` تُلحق `pod_regex` المُقدَّم من المتصل دون فاصل `--`، فيحقن المهاجم تجاوزات Helm `--set` (مثل `tap.docker.registry`) ويعيد توجيه صور العامل إلى سجل يسيطر عليه — اختراق كامل للعنقود (cluster-admin) عند التشغيل مع `--allow-destructive`. المتأثر: v53.1.0 حتى v53.3.0. **الإصلاح: v53.4.0** (PR #1957).
  - **code-review-mcp-server — 1.5.3:** إصلاح أمني (التفاصيل في الاستشارة الأصلية؛ لم تُقرأ الليلة).
- **لماذا يهم ACI:**‏ هذه الدفعة كلها تدور حول **نفس الدرسين اللذين اعتمدتهما ACI**: (1) وسم «قراءة فقط» ليس ضابطًا — أداة موسومة read-only كتبت ملفات؛ (2) مدخلات الوكيل القابلة للتأثير (حقن موجّه) تصل إلى مسارات ملفات ورموز وأوامر Helm. أي خادم MCP يُقيَّم في ACI يجب أن يُفحص ضد هذه الأنماط الثلاثة (تسريب رمز، كتابة خارج الدليل، حقن وسائط) قبل أي توصيل.
- **المصادر:** https://www.pranavaraparla.com/vibe-coding-security/alerts.html (تنبيه 2026-11-16)؛ https://mcp.cve.now/CVE-2026-126681؛ https://www.stateward.com/vulnerabilities/CVE-2026-129235؛ https://www.stateward.com/vulnerabilities/CVE-2026-129236؛ https://github.com/awslabs/mcp/security/advisories/GHSA-mqm3-w68j-75mw
- **الإجراء: watch** — ACI لا يشغّل أيًا من هذه الخوادم الأربعة؛ أضف أنماط الثغرات الثلاثة إلى قائمة فحص قبول خوادم MCP.

## 2. mcp-server-git — تنفيذ أوامر عشوائي عبر إعدادات Git الخاصة بالمستودع (11 نوفمبر، HIGH 7.8)

- **ما الذي تغيّر:** الاستشارة **GHSA-6hqx-gqrx-c5r2** (نُشرت **11 نوفمبر 2026**، **HIGH 7.8**): خادم Git المرجعي `mcp-server-git` ينفّذ أوامر عشوائية عبر إعداد Git الخاص بالمستودع (`core.fsmonitor`) أثناء أدوات «قراءة فقط». **الإصلاح: إصدار 2026.11.11** من حزمة الخوادم المرجعية (مستودع modelcontextprotocol/servers v2.4.0، نُشر 2026-11-11T07:07:16Z).
- **لماذا يهم ACI:**‏ أخطر عنصر في أسبوع MCP: أداة قراءة فقط تنفّذ كودًا لأنها تثق بإعدادات داخل البيانات التي تقرأها — نفس فئة ثغرة Puppet في ملف OSINT الليلة (ثقة في بيانات موقّعة/داخلية). قاعدة ACI: لا أداة «قراءة فقط» تُشغَّل بلا قائمة سماح للأوامر الفرعية التي تستدعيها فعليًا.
- **المصادر:** https://github.com/modelcontextprotocol/servers/security/advisories/GHSA-6hqx-gqrx-c5r2 (HIGH 7.8، عبر GitHub API)؛ https://api.github.com/repos/modelcontextprotocol/servers/releases/latest (v2.4.0)
- **الإجراء: watch** — إن قُيّم mcp-server-git يومًا في ACI، الحد الأدنى هو إصدار 2026.11.11؛ وثّق نمط `core.fsmonitor` في قائمة الفحص.
