# MCP — بوابة MCP بلا خادم من AWS + خادم Fastpath للحوكمة + WooCommerce MCP بكتابة آمنة (9 نوفمبر 2026)

## AWS — بوابة MCP بلا خادم على ECS Fargate لوصول الوكلاء إلى بحيرات البيانات (6 نوفمبر 2026)

- **ما الذي تغيّر:** نشرت AWS على مدونة تعلّم الآلة (6 نوفمبر 2026) معمارية خادم MCP مركزي بلا خادم (ECS + Fargate) لفريق شبكة مراكز الفرز في أمريكا الشمالية: وكيل Bedrock يفسّر الطلبات ويختار الأدوات، وخادم FastMCP يكتشف الأدوات ديناميكيًا من ملف JSON للبيانات الوصفية عند كل مزامنة، دون توصيل نقطة-بنقطة لكل قاعدة بيانات. الضوابط الأمنية مركزية: الخادم في شبكات فرعية خاصة خلف موازن تحميل داخلي، ومصادقة Cognito عبر JWT، وجدار WAF، و**أدوات Athena مقيَّدة بـ SELECT فقط** (يرفض أي كتابة/تعديل/حذف قبل وصولها إلى التخزين)، وBedrock Guardrails لتصفية الحقن في المطالبات، وتسجيل كل استدعاء أداة في CloudWatch كسجل تدقيق مركزي.
- **لماذا يهم ACI:** مرجع تصميمي مباشر لأي تعريض مستقبلي لخادم MCP خاص بـ ACI: قاعدة «البوابة تفرض القراءة فقط» نفسها التي سجّلناها في Cloudflare Access MCP Portals (7 نوفمبر) وبوابة Azure MCP (8 نوفمبر) — الآن بثلاثة تطبيقات سحابية مستقلة تؤكد النمط: الهوية + WAF + قراءة-فقط المفروضة عند البوابة قبل وصول العميل إلى الخادم. لا اعتماد سحابي في ACI اليوم، فسجّل كمرجع فقط.
- **المصادر:** https://www.konsulteer.com/article/aws-develops-serverless-mcp-gateway-to-connect-ai-agents-with-enterprise-data-lakes (نُشر 2026-11-09، عن مدونة AWS ML في 6 نوفمبر 2026) — https://blogs.techbytes.app/posts/serverless-mcp-server-for-ai-agent-data-lake-access-on/ (7 نوفمبر 2026)
- **الإجراء: watch** — مرجع تصميمي لبوابة MCP؛ نمط «SELECT فقط عند البوابة» يُقتبس عند بناء أي خادم MCP في ACI.

## Delinea Fastpath MCP Server — حوكمة وصول للقراءة فقط، معاينة خاصة (نوفمبر 2026)

- **ما الذي تغيّر:** أطلقت Delinea Fastpath خادم MCP لبيانات حوكمة الوصول (المالية والتدقيق وتقنية المعلومات): **23 أداة قراءة فقط** عمدًا فوق بيانات Access Control وAccess Review، تعمل مع Copilot وClaude وChatGPT وGemini Enterprise، في معاينة خاصة لدى عملاء مختارين، والإتاحة العامة (GA) مخططة في **نوفمبر 2026**. يرى كل الأنظمة المتصلة بـ Fastpath (100+ تطبيق ERP/CRM/HCM) فيسأل عن المستخدمين والأدوار ومخاطر الوصول عبرها دفعة واحدة. ندوة تعريفية في 10 نوفمبر.
- **لماذا يهم ACI:** نمط «قراءة فقط عمدًا» ثالث في أسبوع واحد (بعد Memgraph MCP وGraphIQ MCP) — إجماع ناشئ في الصناعة: خوادم MCP الاستخبارية/الحوكمية تُبنى للقراءة أولًا. لمهام ACI: خادم حوكمة وصول ليس مصدرًا مباشرًا، لكن النمط يُقتبس في أي خادم MCP نعرضه.
- **المصادر:** https://msdynamicsworld.com/story/delinea-fastpath-deploys-fastpath-mcp-server-ai-readiness-access-governance-and-audits (نُشر 2 نوفمبر 2026؛ GA مخطط نوفمبر 2026)
- **الإجراء: watch** — نمط قراءة-فقط؛ راقب GA في نوفمبر.

## WooCommerce MCP v0.6.0 — تقرير تقني عن معمارية كتابة آمنة (نوفمبر 2026)

- **ما الذي تغيّر:** تقرير تقني (v1.0، نوفمبر 2026) يحلّل **woocommerce-mcp v0.6.0** (TypeScript، MIT): خادم MCP بـ **47 أداة** (28 قراءة، 19 كتابة) يربط وكلاء LLM بواجهة WooCommerce REST عبر خط أنابيب كتابة آمنة من أربع طبقات: (1) قراءة فقط افتراضيًا، (2) معاينة من مرحلتين بمعرّف SHA-256، (3) كشف تقادم المعاينة ببصمة حالة، (4) موافقات موقَّعة HMAC-SHA256 خارج النطاق. إضافة: تنقيح PII، ومرشحات سماح/منع للأدوات، وتحديد معدل token-bucket، وسجلات تدقيق JSON.
- **لماذا يهم ACI:** ليس مصدر استخبارات مباشرًا، لكنه أوضح توثيق منشور حتى الآن لنمط «الكتابة الآمنة عبر MCP» — إن احتاج ACI يومًا أدوات كتابة (تحديث سجل مهمة، إصدار تنبيه) فهذا هو النموذج المرجعي: معاينة + بصمة حالة + موافقة موقَّعة خارج النطاق، لا كتابة مباشرة من الوكيل.
- **المصادر:** https://www.researchgate.net/publication/417364640_Technical_Report_WooCommerce_Model_Context_Protocol_Server_-_A_Multi-Store_Previewed_Safe-Write_Architecture_for_Autonomous_AI_Agents_in_E-Commerce (تقرير v1.0، نوفمبر 2026)
- **الإجراء: watch** — مرجع معماري لكتابة آمنة عبر MCP.
