# FastMCP 4.1.3 "Root Awakening" — certifi floor after the eMudhra CA key compromise

**Date found:** 2026-10-22 (release shipped 2026-10-20)
**Category:** mcp / supply-chain security

## What changed
- **FastMCP v4.1.3** released 2026-10-20 ("Root Awakening"). Headline item is **security**: it now **requires certifi ≥ 2026.10.19** for certifi-backed server dependencies and optional SDK integrations, following the **eMudhra CA key compromise** (PrefectHQ/fastmcp PR #5945, @zzstoatzz).
- **eMudhra CA compromise (disclosed 2026-10-17 → public 2026-10-20):** a researcher ("Wayne") reported that the private keys of **eight eMudhra intermediate CAs** were trivially recoverable — the April 30, 2025 key ceremony generated weak P-384 keys (whole numbers < 256; one key was literally **4**), and those weak keys were the ones published to root stores. Six intermediates could issue TLS certs for any domain, two could issue code-signing certs. Chrome, Firefox, Apple, Microsoft all blocked them between Oct 17–20; Mozilla removed the **emSign ECC Root CA – G3** from NSS; Chrome removes that root entirely on **2026-10-27**. Cause per eMudhra's Oct 21 statement: a flawed wrap/unwrap step in the key-generation script produced a second weak key set that got published by mistake. No fraudulent certs confirmed in Certificate Transparency logs as of Oct 21, but the keys were effectively public for ~17 months.
- Non-FastMCP items in 4.1.3: public-client OAuth auth fix (#5879), per-server MCP config timeouts (#5758), generator-transform fixes (#5672).

## Why it matters for ACI
FastMCP is ACI's MCP framework of choice (4.1.2 covered Oct 20). The 4.1.3 advisory is explicit that **upgrading FastMCP alone is insufficient** — FastMCP 4 uses the system trust store by default, so the security notice tells operators to update **OS, container, custom, and installer trust stores** too. Any ACI MCP server doing outbound HTTPS (fetch, webhook, API connectors) relies on these trust stores; a compromised CA chain lets a MITM forge any HTTPS endpoint the agents talk to. Also: **2026-10-27 is the hard date** — anything in our infra that still chains to emSign ECC Root CA – G3 breaks on Oct 27 in Chrome-derived trust.
