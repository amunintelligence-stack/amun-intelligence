# دلتا MCP — ثغرة SSRF في بوابة AWS (إصلاح 1.35.0)؛ وحقن وصف أدوات OpenHuman؛ ودورة مواصفات نصف سنوية (12 نوفمبر 2026)

## AWS mcp-gateway-registry — CVE-2026-125926: ثغرة SSRF، الإصلاح في 1.35.0 (كُشف 11 نوفمبر 2026)

- **ما الذي تغيّر:** أصلحت AWS ثغرة **تزوير طلبات من جانب الخادم (SSRF)** في **mcp-gateway-registry** — سجل وبوابة مفتوحا المصدر لخوادم MCP — تسمح لمهاجم موثَّق بالوصول إلى خدمات داخلية عبر البوابة. الثغرة **CVE-2026-125926** تؤثر في الإصدارات **1.0.3 حتى 1.34.0**؛ الإصدار **1.35.0** يحوي الإصلاح. كشفت AWS عنها في **11 نوفمبر 2026** وحثت على الترقية. لا تأكيد لسرقة بيانات اعتماد أو استغلال نشط لهذه الثغرة تحديدًا. يُنسب الكشف المنسق إلى الباحث novice-22. ثغرة منفصلة في واجهة الإدارة الخارجية أُصلحت في 1.25.0.
- **لماذا يهم ACI:** بوابة AWS MCP كانت مرجع تصميم سُجل في 6 نوفمبر (بوابة MCP بلا خادم: ECS Fargate + FastMCP + Bedrock، اكتشاف ديناميكي للأدوات، JWT عبر Cognito، WAF) — وهي الآن تحمل أول ثغرة SSRF موثقة في هذا النمط. الدرس المعماري: أي بوابة MCP مستقبلية في ACI يجب أن تفرض قائمة سماح صارمة للشبكة الصادرة (egress allowlist) ولا تعتمد على مصادقة الطلب وحدها. لا أثر مباشر: ACI لا يشغّل هذه البوابة.
- **المصادر:** https://cybersecuritynews.com/aws-mcp-gateway-security-flaw/ (12 نوفمبر 2026، 13:51 UTC)
- **الإجراء: watch** — سجّل SSRF عبر البوابة كنمط تهديد في معايير تصميم أي بوابة MCP مستقبلية؛ لا اعتماد.

## OpenHuman — CVE-2026-54140: حقن عبر وصف أداة MCP، CVSS 8.3 (نُشر 11 نوفمبر 2026)

- **ما الذي تغيّر:** نُشرت ثغرة **CVE-2026-54140** في **OpenHuman** (تطبيق سطح مكتب مفتوح المصدر يستخدم وكلاء ذكاء اصطناعي عبر خوادم MCP): خادم MCP خبيث أو مخترَق يستطيع حقن تعليمات عشوائية في سياق نموذج الوكيل عبر أوصاف أدوات غير معقَّمة، مما يتيح تسريب بيانات صامتًا وإجراءات غير مصرح بها. جميع الإصدارات **قبل 0.57.13** متأثرة. الإصلاح في **0.57.13** (صدر 3 يونيو 2026، PR #3215): تعقيم أوصاف الأدوات البعيدة + حدود طول + تسجيل المحاولات. الدرجة **CVSS 8.3 (High)**، CWE-1427 (تعقيم غير سليم لمدخلات تُستخدم في توجيه LLM).
- **لماذا يهم ACI:** هذه أول حالة موثقة لثغرة حقن عبر **وصف الأداة نفسه** — أي أن أي أداة MCP يقدمها طرف ثالث هي سطح هجوم حتى قبل استدعائها. قاعدة تصميمية لـ ACI: عامل أوصاف أدوات MCP الخارجية كمدخلات غير موثوقة، وعقّمها قبل إدخالها في السياق، تمامًا كما نعامل مخرجات الأدوات.
- **المصادر:** https://i10x.ai/news/cve-2026-54140-openhuman-mcp-tool-description-injection (11 نوفمبر 2026)؛ GHSA-g6j9-89xv-v752
- **الإجراء: watch** — أضف تعقيم وصف الأداة إلى قائمة فحص أمان MCP في ACI؛ لا أثر مباشر (لا OpenHuman في المكدس).

## متابعة — CVE-2026-41902 / CVE-2026-41904: تأكيد الإصلاح في إصدار 2.4.0

- **ما الذي تغيّر:** الثغرتان المنشورتان في 8 نوفمبر 2026 في الخوادم الرسمية (هروب حصر في mcp-server-git، وتجاوز SSRF في mcp-server-fetch — حينها بلا تصحيح وتحت المراجعة) هما نفس الثغرات التي أصلحها إصدار **MCP Servers v2.4.0** في 11 نوفمبر (GHSA-6hqx-gqrx-c5r2 / GHSA-3rxj-6jhw-qfv7 ضمن 6 ثغرات). التصحيح مؤكد الآن من مصدرين مستقلين.
- **لماذا يهم ACI:** يغلق هذا الملف؛ الحد الأدنى الثابت لأي استخدام مستقبلي لـ MCP في ACI يبقى كما سُجل في 11 نوفمبر: filesystem 2.3.0، وgit/fetch بتاريخ 2026.11.11.
- **المصادر:** https://falifuentes.com/rafael-fuentes-2026-11-09-am-en/ (9 نوفمبر)؛ ملف 2026-11-11-mcp-servers-2-4-0-security
- **الإجراء: ignore** (متابعة مؤكدة، بلا جديد).

## المواصفة — دورة إصدار ثابتة نصف سنوية؛ التالية 2027-03-30

- **ما الذي تغيّر:** نقل مشرفو MCP المواصفة إلى **دورة إصدار ثابتة كل ستة أشهر** (SEP-3398): الإصدار التالي **2027-03-30** (آخر ثلاثاء من مارس وسبتمبر). تذكير: مواصفة 2026-07-28 أهملت Roots وSampling وLogging مع نافذة إزالة 12 شهرًا (قد تختفي حول يوليو 2027).
- **لماذا يهم ACI:** إيقاع متوقع للمواصفة يسمح بتخطيط ترقيات SDK قبل ستة أسابيع من كل إصدار؛ ونافذة إزالة Roots/Sampling/Logging تقترب — أي خادم MCP مستقبلي يجب ألا يعتمد عليها.
- **المصادر:** https://ai-digest.fjgarciahurtado.com/topics/tooling/mcp/ (حالة 12 نوفمبر 2026)
- **الإجراء: watch** — سجّل تاريخ 2027-03-30 في تقويم المراجعة.
